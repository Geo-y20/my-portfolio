# my-portfolio

George Youhana's portfolio site: Next.js (App Router, plain JavaScript/JSX), deployed on Vercel. All images and demo videos live in Neon object storage (S3-compatible), not in the repo. The Ask AI chat runs as a Route Handler that proxies to OpenRouter.

## Develop

```sh
npm install
cp .env.example .env     # fill in values (never commit .env)
npm run dev              # http://localhost:3000
npm run build            # production build
npm start                # serve the production build
npm run lint
```

Node 20+ (developed on Node 24).

## Structure

```text
app/
  layout.jsx                  html shell: fonts, metadata, header, <main>, footer, chat, <Enhancements/>
  page.jsx                    home: hero + metrics, Work (4 featured + filters), Experience, Skills, About + Education, Contact
  all-projects/page.jsx       archive of every project, same card component + filter bar
  [caseSlug]/                 case-study pages (/case-study-atr-gpt, …), driven by content/case-studies/
  not-found.jsx               404
  sitemap.js, robots.js       /sitemap.xml, /robots.txt
  api/chat/route.js           POST /api/chat → OpenRouter
  api/media/[...key]/route.js GET /api/media/<key> → 302 to a signed object-storage URL
  globals.css                 design tokens + every component
  fonts.js, fonts/            Work Sans + JetBrains Mono (self-hosted variable woff2, via next/font/local)
components/                   Header, Footer, ChatWidget, Enhancements, FilterableProjects, ProjectCard,
                              SectionHead, MediaSlot, LazyVideo, Icon, case-study/, diagrams/
content/
  site.js                     profile, hero metrics, experience, skills, education, certifications, contact
  projects.js                 every project card (featured, more production work, research & personal)
  case-studies/               one file per case study + index.js (order drives the prev/next pager)
  media-manifest.json         generated by `npm run media:upload` — do not edit by hand
lib/
  media.js                    mediaUrl(), hasMedia(), SITE_URL
  storage.js                  S3 client + signed URLs (server only)
  portfolio-context.js        the only facts the chatbot may use — keep in sync with the CV and content/
  metadata.js                 per-page title/description/OG helper
scripts/upload-media.mjs      media sync (see Media)
```

Server Components by default; only the interactive pieces (header menu, filters, chat, reveal/counter animation) are client components. All text and numbers are server-rendered, so the site reads correctly for ATS tools, scrapers and link previews.

Editing copy: change `content/site.js`, `content/projects.js` or `content/case-studies/*`, then keep `lib/portfolio-context.js` in sync.

Old URLs redirect permanently (`next.config.mjs`): `/index.html` → `/`, `/<page>.html` → `/<page>`, and `case-study-sales-intelligence` / `case-study-sheet-chat` → `/case-study-text-to-sql`.

## Media

Media is stored in the Neon bucket and listed in `content/media-manifest.json`. Only objects marked `public` there are rendered on the site or served by `/api/media`; anything else stays private.

1. Put files in `images/` (key = path relative to `images/`, e.g. `projects/foo.webp`, `profile-560.webp`) or `media-staging/` (e.g. `work/speech-ai/demo.mp4`). Both are local sources only.
2. Run `npm run media:upload` (`-- --dry-run` to preview). It uploads new/changed files to the bucket and rewrites `content/media-manifest.json` from what is actually in the bucket. Private keys/prefixes are listed in `scripts/media-visibility.json`.
3. Commit the updated manifest. Cards and case studies pick files up automatically: `MediaSlot` shows the real image/video when its key is in the manifest and a placeholder (icon + stack caption) otherwise, so a missing file never renders as a broken image.

**All screenshots and demos must use mock or blurred company data.**

URLs: by default media goes through `/api/media/<key>`, which redirects to a presigned GET URL. Signatures are pinned to 6-hour windows (valid 12 h), so the redirect is cacheable by browsers and Vercel's CDN. If the bucket is made publicly readable or fronted by a CDN, set `NEXT_PUBLIC_MEDIA_BASE_URL` and files are linked directly.

Expected keys include `profile-560.webp`, `og-image.png`, `favicon.ico`, `favicon.svg`, `apple-touch-icon.png`, `projects/*.webp`, `architecture/*.svg` and `work/<slug>/cover.webp` (+ optional `demo.mp4` / `demo.webm`) for each case study.

## Environment variables

| Name | Used by |
| --- | --- |
| `OPENROUTER_API_KEY` | `/api/chat` (required for the chat) |
| `OPENROUTER_MODELS` | optional comma-separated model chain override |
| `NEON_S3_ENDPOINT`, `NEON_S3_ACCESS_KEY_ID`, `NEON_S3_SECRET_ACCESS_KEY`, `NEON_S3_REGION` | `/api/media` signing and `npm run media:upload` |
| `NEON_S3_BUCKET` | bucket name (default `images`) |
| `NEXT_PUBLIC_MEDIA_BASE_URL` | optional: link media directly from a public bucket/CDN |
| `NEXT_PUBLIC_SITE_URL` | optional: canonical origin for metadata, sitemap and OG URLs |

Vercel reserves the `AWS_*` names, so production must use the `NEON_S3_*` names. Locally, `AWS_ENDPOINT_URL_S3` / `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `AWS_REGION` in `.env` also work as fallbacks. See `.env.example`.

## Chatbot

`/api/chat` proxies to OpenRouter's free models. Set `OPENROUTER_API_KEY` in Vercel → Settings → Environment Variables (Production + Preview), then redeploy. Free model IDs get retired without notice; the chain ends with `openrouter/free`, and you can override it without a code change via `OPENROUTER_MODELS="model-a,model-b"`. Requests are validated and rate-limited per instance; failures are logged in the Vercel function logs.

## Résumé

The Resume buttons link to a Google Drive file (`profile.resumeUrl` in `content/site.js`). To update it, open the file in Drive → Manage versions → Upload new version; the link stays the same, so no deploy is needed. Keep the file shared as "Anyone with the link".
